# Host-based Mitigation of Keystroke Injection Attacks via Emulated Peripherals

This repository contains a host-based system for detecting keystroke injection attacks generated by emulated HID peripherals.

The project combines a Python-based host detection daemon with a CircuitPython HID test environment. The daemon monitors keyboard activity and identifies suspicious behavior using typing speed, timing consistency, blacklisted strings, hotkeys, and hotkey-string sequences.

A SQLite database and Streamlit interface are used to manage detection rules and review detection results.

The project includes:

* Host-side keystroke monitoring and detection
* CircuitPython-based HID attack simulation
* Automated typing-speed and human-like typing tests
* Keystroke injection testing dataset
* SQLite-based detection logging
* Configurable blacklist rules
* Streamlit-based rule and log management

Description: Monitors global keyboard input using `pynput` and analyzes keystroke behavior to detect possible automated HID injection.

Detection includes:

* Typing-speed analysis
* Typing timing-consistency analysis
* Blacklisted string detection
* Blacklisted hotkey detection
* Hotkey + string sequence detection
* Detection cooldown and event tracking
* SQLite-based detection logging

### 2. HID Test Environment

Folder: `/hid/`

Description: CircuitPython-based HID testing environment used to generate automated keyboard input and evaluate the host-side detection daemon.

The HID runner supports:

* Text input
* Individual key events
* Keyboard combinations
* Configurable delays
* Multiple fixed typing-speed profiles
* Automated speed sweeps
* Human-like randomized typing
* Safety filtering for disruptive keyboard combinations
* CSV result logging

The implementation was tested using a Raspberry Pi Zero 2 W running CircuitPython 10.1.4.

Main file:

`hid/code.py`

### 3. Keystroke Injection Dataset

File:

`hid/dataset.json`

Description: Dataset created to test both malicious HID behavior and potential false-positive conditions.

The dataset includes:

* Normal text
* Normal keyboard shortcuts
* Suspicious command-like text
* Hotkey + string attack sequences
* False-positive test cases
* Borderline and evasive input patterns

Examples include normal user input, administrative commands, command-line utilities, modified suspicious strings, and common attack sequences such as launching a command interface through keyboard shortcuts.

## Detection Methods

### Typing Speed

The daemon measures character timing across recently completed words.

Typing significantly faster than the configured human typing threshold may indicate automated HID input.

---

### Timing Consistency

Automated devices can generate keystrokes at more consistent intervals than normal human typing.

The daemon tracks recent average character delays and analyzes their standard deviation to identify unusually consistent typing behavior.

---

### Blacklisted Strings

Recent keyboard input is compared against configurable strings stored in the SQLite database.

This can identify suspicious command-line or administrative input associated with keystroke injection attacks.

---

### Blacklisted Hotkeys

The daemon monitors keyboard combinations involving modifier keys such as:

* `CTRL`
* `SHIFT`
* `ALT`
* `GUI`

Configured combinations can be detected and logged independently.

---

### Hotkey + String Sequences

The system can associate a detected hotkey with text entered shortly afterward.

This allows multi-step sequences such as:

`GUI + R → cmd`

or:

`GUI + R → powershell`

to be detected as combined events.

---

## Testing

The HID environment reads sequences from:

`hid/dataset.json`

and executes them against the host running the detection daemon.

Fixed-delay speed profiles are used to test detection behavior across different typing speeds.

The HID runner also supports randomized human-like typing with:

* Variable character delays
* Random pauses
* Multiple human-like test runs

Test results can be logged to:

`hid/result_log.csv`

## Running the Detection Daemon

Navigate to the daemon folder:

```bash
cd daemon
```

Run:

```bash
python daemon_run.py
```

A custom database can also be specified:

```bash
python daemon_run.py --db <database_path>
```

---

## Running the Management Interface

From the `daemon` directory:

```bash
streamlit run user_settings.py
```
